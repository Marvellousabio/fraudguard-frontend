# FraudGuard — Hackathon-Winning Fraud Prevention Ideas

> Research compiled for the FraudGuard frontend project. Focus: ideas that can be implemented within a React/TypeScript frontend dashboard to prevent fraud before it happens.

## Top 3 Ideas — Best Fit for FraudGuard

These are the ideas most immediately implementable in FraudGuard's architecture (React/TypeScript frontend with mock backend via offlineBypass.ts).

### 1. TriShield Ensemble — Multi-Layer ML Fusion for Real-Time Prevention (23ms)\n\n**Source:** V HACK 2026 (USM) — Champion; Project: FraudShield AI by team 3 Potatoes\n\n**What it does:** A three-layer ML fusion of LightGBM + Isolation Forest + behavioral profiling that catches evolving fraud patterns in 23ms. Dual-threshold calibration minimizes wrongful blocks. Closed-loop retraining pipeline learns from admin decisions in real time. Fully PDPA and GDPR compliant through irreversible PII hashing.\n\n**Why it fits FraudGuard:**\n- Client-side scoring can be done with a pre-trained LightGBM or ONNX model loaded in the browser via onnxruntime-web\n- Behavioral profiling (mouse movements, keystrokes, session timing) is data the frontend already has access to\n- The 23ms latency target is achievable for pre-transaction scoring in JS\n- PII hashing aligns with the privacy-aware approach already used in the project\n\n### 2. KAWAL Progressive Friction + Explainable Actions\n\n**Source:** V HACK 2026 (USM) — Best Market Potential Award; Project: KAWAL — Fraud Shield for the Unbanked\n\n**What it does:** Real-time ASEAN-aware fraud decisioning platform. Uses XGBoost scoring, graph-based fraud ring detection, and user behavior profiling. Instead of a binary block/allow, provides explainable APPROVE / FLAG / BLOCK actions. Optimized for QR codes and remittances in unbanked populations. Includes tamper-evident audit logging.\n\n**Why it fits FraudGuard:**\n- The analyst dashboard can display decision labels and reason codes natively\n- Graph-based fraud ring detection can be visualized in existing chart components\n- Progressive friction (not just hard block) improves user experience\n- Explainable actions help analysts understand why a transaction was flagged\n\n### 3. OneRadar — Real-Time Prediction Using Alternate Data Sources\n\n**Source:** RBI HaRBInger 2024 — Winner; by FPL Technologies\n\n**What it does:** Real-time prediction, detection, and prevention of fraud in financial transactions using alternate sources of data including publicly available information. Visual color-coded screen for alerting customers, capturing their feedback, and feeding it into a decision strategy model. Expert platform reviews feedback and further enhances the model. Aims for high fraud prevention with reduced false positives and minimized latency.\n\n**Why it fits FraudGuard:**\n- Alternative data enrichment can be done client-side (IP geolocation, device fingerprint from the browser)\n- The feedback loop concept maps naturally to the analyst dashboard (analysts mark false positives/negatives)\n- Color-coded screens fit the existing dashboard aesthetic\n- The mock backend (offlineBypass.ts) can simulate alternate data sources\n\n### 4. FraudNet·AI — Live 3D Graph + Multi-Algorithm Detection\n\n**Source:** GenAI Genesis 2026 (Canada) — Winner; by Ajay Maan\n\n**What it does:** Transactions stream over WebSocket into a live 3D WebGL force-directed graph. Every 30 edges, the fraud detection engine re-runs five parallel detection algorithms and emits alerts as patterns emerge. IBM Granite 3 LLM explains every finding in plain language for investigators. Built in 36 hours.\n\n**Why it fits FraudGuard:**\n- The 3D graph visualization can be added to the analytics dashboard using Three.js or React Three Fiber\n- Multi-algorithm parallel detection can be simulated in the mock layer\n- LLM-based explanations can be added to the analyst alert panel\n- WebSocket streaming maps to FraudGuard real-time data already in the project\n\n### 5. Realytic — Deepfake & Fraud Detection in TEE\n\n**Source:** V HACK 2026 (USM) — Peoples Choice Award; by team 3004\n\n**What it does:** Privacy-preserving, multi-modal deepfake detection running inside a Trusted Execution Environment (TEE). Covers image, video, and audio deepfakes. Includes a fraud analysis pipeline that transcribes speech, redacts private data, and uses a hybrid risk engine to detect scams across web and native apps simultaneously.\n\n**Why it fits FraudGuard:**\n- While TEE requires backend support, the frontend can integrate with the detection pipeline\n- Deepfake detection is relevant if the product handles identity verification flows (e.g., onboarding screenshots)\n- The transcription and redaction pipeline could be mirrored in a frontend pre-screening step\n\n### 6. HSBC Traffic Light — XGBoost + Autoencoder Hybrid\n\n**Source:** HSBC Hackathon 2025; Project: AI-Powered Fraud Detection System\n\n**What it does:** Hybrid system using XGBoost for individual transaction scoring and Deep Autoencoders for anomaly detection. Traffic light operational logic classifies transactions into Green (auto-approve), Yellow (flag for review), Red (auto-block). Results: 92% of customers approved automatically, only 6% sent for review, successfully blocked whale attacks and velocity attacks.\n\n**Why it fits FraudGuard:**\n- The traffic light framework (Green/Yellow/Red) directly maps to a dashboard UI component\n- Autoencoder anomaly detection can run client-side with ONNX.js\n- The XGBoost model can be pre-trained and loaded in the browser\n- Works with the existing mock data in offlineBypass.ts\n\n### 7. GBM + LSTM + GNN — Three-Architecture Hybrid\n\n**Source:** Multiple hackathon prototypes; Project: Hackathon-AI-Fraud-Detection\n\n**What it does:** A comprehensive prototype demonstrating three parallel AI techniques working together: GBM (Gradient Boosted Models) for real-time transaction scoring, LSTM for behavioral drift detection over time, and GNN-ready architecture for network-level fraud detection. Catches both isolated anomalous transactions and coordinated fraud networks simultaneously.\n\n**Why it fits FraudGuard:**\n- GBM scoring can run client-side; LSTM drift detection can feed into the dashboard\n- GNN ring detection can be visualized as the analyst dashboard graph view\n- The three-architecture approach ensures coverage across fraud types (isolated, temporal, network)\n\n### 8. Detects the rhythmic pattern of deposits and rapid withdrawals that characterize mule behavior.\n\n**Why it fits FraudGuard:**\n- Mule detection can be visualized in the dashboard as transaction flow patterns\n- The mock backend can simulate mule account behavior with specific transaction sequences\n- Analyst dashboard can show flagged accounts with transaction flow timelines\n\n### 9. Mobile Banking Pre-Auth — Network-Level Signal Checks\n\n**Source:** Vonage Holiday Hackathon 2024; Project: Mobile Banking Fraud Prevention\n\n**What it does:** Proactive fraud detection using network APIs to verify identity and assess transaction risk before it executes. It uses a mock backend (offlineBypass.ts) that intercepts API calls via a fetch override and returns simulated responses. The following ranking considers implementation feasibility within this architecture.\n\n### Tier 1 — Implement Immediately (Frontend Only)\n\nThese ideas require zero backend changes and can be implemented using the existing offlineBypass.ts mock layer and React dashboard components.\n\n1. **KAWAL Progressive Friction** — Add APPROVE/FLAG/BLOCK decision labels to alerts in AnalystDashboard.tsx. Color-code rows and add expandable reason panels. Works with existing mock data by adding a riskAction field to mock responses.\n\n2. **SecureSwipe Pre-Transaction Blocking** — Extend initOfflineBypass() in offlineBypass.ts to compute a risk score before returning mock responses. For /auth/ endpoints, return 403 for high-risk logins. For /api/ endpoints, return action=BLOCK for high-risk transactions. The analyst dashboard then shows blocked vs. approved transactions visually.\n\n3. **HSBC Traffic Light Framework** — Implement Green/Yellow/Red classification in the mock scoring logic. Green transactions pass through normally, Yellow triggers a flag in the dashboard, Red blocks and requires verification. This maps directly to existing dashboard components.\n\n4. **OneRadar Alternate Data Simulation** — Add simulated alternate data sources (device fingerprint, IP geolocation, session context) to the mock responses. Show a data enrichment panel in the dashboard before the transaction is processed.\n\n5. **Mobile Banking Pre-Auth (Network Signals)** — Add SIM status, roaming, and geolocation checks to the offlineBypass mock layer. Return a risk score based on these signals before allowing the transaction through to the mock backend.\n\n### Tier 2 — Implement with Minor Backend Integration\n\nThese ideas need a backend service or external integration but can be prototyped on the frontend using mock data first.\n\n6. **TriShield Ensemble (23ms scoring)** — Load a pre-trained ONNX/LightGBM model via onnxruntime-web in the browser. Score transactions client-side before they hit the mock backend. Add a risk score bar to each dashboard row. Behavioral profiling data is gathered passively from frontend interactions.\n\n7. **SecureSwipe Feedback Loop** — Add a feedback mechanism in the analyst dashboard where analysts can mark alerts as true positive or false positive. Feed this back into the mock scoring logic to simulate continuous learning.\n\n8. **GBM+LSTM+GNN Hybrid** — Frontend can already display GNN-detected fraud rings as interactive graphs (using the existing AnalyticsCharts.tsx components). LSTM behavioral drift can be shown as a timeline in the dashboard. GBM scoring can be simulated with the existing mock data.\n\n9. **Mule Account Detection (Flow Visualization)** — Add a transaction flow visualization panel showing money moving between accounts. Flag accounts with rhythmic deposit-withdrawal patterns as potential mules.\n\n10. **CBDC Privacy-Preserving Simulation** — Add privacy-preserving checks to the mock layer: hash PII before processing, and show how risk decisions can be made without exposing raw data. Demonstrate GDPR/PDPA compliance visually.\n\n### Tier 3 — Lower Fit for This Project\n\nThese ideas are valuable but require significant infrastructure that goes beyond a frontend dashboard scope. They are worth noting for future roadmap consideration.\n\n11. **FraudNet·AI 3D Live Graph** — Full GNN-based graph detection requires backend graph engines (Neo4j, NetworkX, GPU inference). The frontend visualization part (Three.js/React Three Fiber) is feasible but the detection engine is backend-oriented.\n\n12. **Realytic Deepfake TEE** — Requires media processing pipelines and Trusted Execution Environment infrastructure. More relevant for identity verification platforms than transaction dashboards.\n\n## Summary\n\nThe most impactful fraud prevention ideas for FraudGuard are those that work within the existing architecture:\n\n- **Immediate wins** — Extend offlineBypass.ts to add pre-transaction scoring, implement the Traffic Light framework (Green/Yellow/Red), and add decision labels (APPROVE/FLAG/BLOCK) to the analyst dashboard. These require only frontend changes and use the existing mock backend.\n\n- **Near-term wins** — Add ONNX-based client-side ML scoring, build a feedback loop for analysts to mark false positives/negatives, and create a transaction flow visualization panel for mule detection. These require minor integration work but stay within the project scope.\n\n- **Future roadmap** — GNN graph detection, live 3D graph visualization, and deepfake detection. These require backend infrastructure but can be prototyped with mock data on the frontend first.\n\nThe key insight from all winning hackathons: **fraud prevention is most effective when it happens before the transaction completes**, not after. FraudGuard already has the frontend architecture to intercept and score transactions — the winning ideas simply add the scoring logic, decision framework, and visual feedback needed to make prevention actionable.\n\n---\n\n*Research compiled from: HSBB Hackathon 2025, RBI HaRBInger 2024, GenAI Genesis 2026, V HACK 2026, SecureSwipe Hackathon, Vonage Hackathon 2024, Indian Bank PSBS Hackathon 2026, and multiple academic/industry sources.*\n
